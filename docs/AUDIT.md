## 2. プロジェクト構成と起動の流れ

```
Packages/com.worldsim.core/Runtime   約3,900行  世界・経済・交通・環境・保存（ルールはすべてここ）
Packages/com.worldsim.core/Tests     約1,400行  NUnit 89件
dotnet/WorldSim.Web                  GameApi.cs 556行（JS連携27メソッド）＋ app.js 1,292行 ＋ index.html 248行
dotnet/WorldSim.Cli                  ヘッドレス実行・地図PNG・性能計測・保存サイズ計測
UnityProject/Assets/WorldSim/Scripts 約1,100行（未検証）
```

**ブラウザ版の起動**［確認］：`index.html` → three.js → `blazor.webassembly.js`（`framework/`へ読み替え）→ `GameApi.Init(seed)` → `WorldFactory.Create`（地形→町→住民→雇用）→ `BranchManager` → 毎フレーム `GameApi.Tick(dt)` → `SimulationRunner.Update` → 1時間ごとに日次システムを1つずつ実行 → JSが版番号を見て変化した層だけ描き直す。

**主要な依存関係**［確認］：表示（Web/Unity/CLI）→ `GameApi`等の薄い窓口 → `IWorldCommand` → `WorldState` → 各 `ISimulationSystem`。Coreから表示への依存はない。

## 3. 現在の実装状況

### 実際に動作するもの［確認：自動テスト・ヘッドレスブラウザ・長時間実行］
- 地形の生成・編集、建物・道路の建設と撤去（費用・検証付き）、森林の伐採・汚染被害・再生
- 住民（年齢・学歴・住居・職場・通勤・購買・満足度・出生・死亡・移住・転居・転職）
- 企業（3段階の生産網・在庫・故障・倒産と再開・配当・技術導入）、物流（地元取引・輸出入・運賃）
- 交通量の割当てと渋滞、価格の変動、税・補助・年金・失業手当、電力、汚染、天候、洪水・地震と復旧
- 統計・原因診断・予測、セーブ／ロード（途中保存からの完全な再開）、歴史分岐と比較
- ブラウザ版：3D表示、3種類のカメラ、建設UI、各パネル、タッチ操作
- 10年連続実行：1日あたり3.8ms、メモリ8.4MB、人口887人で安定、お金の総量は常に一致

### 一部だけ実装されているもの
| 機能 | 状態 |

| 通行人の表示 | 朝夕の通勤者を点で表示。**予定の計算がWeb側（GameApi）にあり、Coreにない**［確認］ |

| 建物 | 箱の描画のみ。内部・出入口・設備はない［確認］ |
| 政治 | 1都市の政策のみ。国家・外交はない［確認］ |
| 拡張性 | 定義はJSONで外部化・検証済み。ただし利用者がMODを読み込む手段がない［確認］ |
| モバイル | タッチ操作・画質の簡易調整あり。実機での性能測定はしていない［未確認］ |

### 仮の表示・ダミー
- Unity版の画面全体（未検証）。ブラウザ版の「概要」タブにある「まだ無い機能」の一覧は、意図的な未実装の表示であり、ダミー機能はない［確認］。

### 未実装
人物の操作、建物内部、人間関係、家賃・住宅市場、複数都市・国家・外交、鉄道・港、生態系（動物）、ゲームモード、シナリオ編集、MOD読込、AI提案、マルチプレイ。

### 重複・責務があいまいな箇所［確認］
1. **住民の1日の予定**が `GameApi.GetAgents`（Web側）にしかない。人生体験モードやUnity版でも必要になるため、Coreへ移すべき。
2. **地面の色分け**が Web（app.js）、Unity（TerrainView）、CLI（MapRenderer）に3重に存在。
3. `app.js` が1ファイル1,292行。描画・入力・UI・保存がすべて同居している。
4. コマンドに「誰が実行したか」がない。人生体験モードの権限や、将来のマルチプレイの権限確認ができない。

### 不具合・警告・性能［確認］
- ビルド警告0、テスト失敗0。ブラウザでのエラー0（自動テストの範囲）。
- 重い処理は Retail（1.3ms/日）と Traffic（1.1ms/日）。住民数と店舗数に比例する。
- **保存データが履歴とともに増え続ける**（10年で2.6MB、JSON生成にネイティブで135ms）。ブラウザの保存領域（目安5MB）を20年前後で超える恐れがある。WebAssemblyでは生成に数秒かかる可能性がある［推測］。

## 5. 設計上の問題と技術的リスク

| # | 問題 | 影響 | 優先度 |
|---|---|---|---|
| R1 | 時間の最小単位が1時間。人物の歩行や会話は秒〜分単位 | 人生体験モードの時間の扱い | 高 |
| R2 | コマンドに実行者（権限）がない | 人生体験モード・マルチプレイ | 高 |
| R3 | 住民に名前・位置・人間関係・能力がない | 人生体験モード | 高 |
| R4 | 1つのマップ（128×128マス、1.28km四方）・1都市が前提。地形メッシュも1枚 | 広大な世界・複数都市 | 高（中長期） |
| R5 | 住民を全員個別に毎日計算。集約計算がない | 人口の大規模化 | 中長期 |
| R6 | 保存データの肥大化と移行の仕組みの欠如 | 長期プレイ・互換性 | 中 |
| R7 | app.js の肥大化、色分け処理の3重化 | 保守性 | 中 |
| R8 | Unity版が未検証のまま差が広がっている | 第5章の方針との整合 | 判断事項 |
| R9 | 浮動小数点のため、異なるCPU間で計算結果が一致する保証がない | マルチプレイの同期方式 | 低（将来） |
| R10 | 経済の均衡が手調整の定数に依存（失業率は約10%で安定） | 新しい要素を足すたびに再調整が必要 | 中 |
