# 人生体験モード 設計書（第1段階）

仕様提案「一人の人物として人生を歩むライフシミュレーションモード」を、既存の構造に接続するための設計。
**前提：別の世界・別の経済を作らない。操作中の人物は、判断をプレイヤーが行うだけの普通の住民である。**

---

## 1. 概念の分離

| 概念 | 何を決めるか | 置き場所 | 保存 |
|---|---|---|---|
| **モード（権限）** | 何を操作できるか。世界創造者＝世界の編集・管理、住民＝自分の生活の行動だけ | Core の `Actor`（コマンドの実行者） | しない（遊び方の設定） |
| **操作中の人物** | どの住民を動かしているか、その位置・行動・欲求 | Core の `PlayerState`（世界の状態の一部） | する |
| **視点（カメラ）** | どこから見るか：俯瞰・自由・一人称・三人称 | 表示層 | しない |
| **時間の速さ** | 1時間が何秒か（停止・生活・1×・4×・16×） | 表示層の設定（実行器） | しない |

- 視点を変えても権限は変わらない。人生体験モードで俯瞰にしても、見るだけで編集はできない。世界創造者モードで一人称にしても権限はそのまま。
- 人物を操作していても世界の時間は止まらない。速さは選べるが、ルールはどの速さでも同じ（既存テストで保証済み）。
- 権限の確認はCoreで行う。表示層でボタンを隠すだけにはしない（将来のマルチプレイに必要）。

## 2. データの追加（すべて保存対象）

**住民（Citizen）に追加** — 全住民に共通。特別扱いは「判断を自動で行うかどうか」だけ。
| 項目 | 意味 | 他の住民での使われ方 |
|---|---|---|
| 名前 | 住民IDから決まる日本語の氏名（保存不要） | 情報パネル・会話 |
| 勤続日数 | 同じ職場で働いた日数。半年ごとに昇進（賃金+4%、最大+12%） | 全員に適用 |
| 人間関係 | 相手IDと親しさ（0〜1）。会話で増え、少しずつ減る | 会話した相手のみ記録 |

**操作中の人物（PlayerState）**
| 項目 | 意味 |
|---|---|
| 住民ID | 0なら誰も操作していない |
| 位置・向き | 屋外では世界座標（m）、屋内では部屋の座標 |
| いる建物 | 0なら屋外 |
| 行動 | 待機・歩行・睡眠・仕事・勉強・移動中 |
| 空腹・体力 | 0〜1。時間とともに減り、食事・睡眠で回復 |
| 食料の備蓄 | 店で買った食料の個数（家で食べる） |
| 本日の勤務時間・欠勤日数 | 給料は勤務時間に比例、無断欠勤が続くと解雇 |
| 学習の進み具合 | 職業訓練で学歴が上がる |
| 移動の到着時刻 | 「行き先へ移動」中の到着時刻（道路網の所要時間） |

## 3. 既存システムとの接続

| 既存 | 変更点（操作中の人物のみ。他の住民はこれまで通り） |
|---|---|
| Labor（雇用） | 自動の求職・転職をしない。解雇・倒産による失業は他の住民と同じ |
| Retail（日々の買い物） | 自動で買わない。自分で店に行き、店の在庫と台帳を使って買う |
| Finance（給料） | 給料＝賃金×勤務時間/8（他の住民は満額）。勤続による昇進は全員共通 |
| Population（人口） | 自動の転居・移住・死亡をしない。被災・建物の撤去で家を失うのは同じ |
| Traffic（交通） | 移動の所要時間は既存の道路網（渋滞・技術・被災を含む）で計算 |
| 新規 AvatarSystem（1時間ごと） | 欲求の減少・回復、勤務時間の加算、到着の処理 |
| 新規 DailySchedule | 住民の1日の予定（自宅・通勤・仕事・買い物・余暇・学校）。Webの通行人表示もこれを使う |

**連動の例（テストで確認する）**：勤務先が倒産→失業／道路を切る→通勤の所要時間が延びる／物価が上がる→買い物の支払額が増える／新しい工場→求人に現れる／被災→家が使えない／技術導入→職場の必要人数が減り解雇される場合がある。

## 4. 新しい操作（コマンド）

世界創造者だけ：建設・道路・撤去・地形・政策・研究・災害（既存）。
住民（操作中の人物）だけ：
| コマンド | 条件 |
|---|---|
| 人物を操作する／新しく作る／操作をやめる | 作成時は空き住宅が必要。お金は外部から転入 |
| 歩く | 屋外では建物の中を通れない・水中は不可・1回の移動距離に上限 |
| 入る／出る | 出入口の近くにいること。自宅・自分の職場・営業時間中の店・開館時間中の公共施設 |
| 設備を使う | ベッド（睡眠）・冷蔵庫（食事）・レジ（買い物）・作業台など（仕事）・掲示板（求人）・教室（訓練） |
| 買う | 店の在庫・価格（市場価格×利幅）・所持金。売上は店へ |
| 就職・退職 | 欠員があること、自宅から通えること、必要な学歴 |
| 転居 | 空き住宅（費用5万円） |
| 話す | 同じ建物にいる住民（予定から判定）または家族 |
| 行き先へ移動 | 自宅・職場・店・公共施設へ道路で移動。所要時間は道路網から計算 |

## 5. 建物内部（第1段階）

建物の種類ごとに、1部屋の内装を定義データ `interiors.json` に置く（部屋の大きさ・出入口・設備の種類と位置）。
画面では部屋を3Dで表示し、その時刻に予定上そこにいる住民（家族・同僚・客）を人型で表示する。

## 6. 時間の尺度

世界は1時間単位のまま。速度に「生活（1時間＝20秒）」を追加し、人生体験モードの既定にする。
建物や部屋の中を歩く時間は世界の時間に含めない（見た目の移動）。町の中の長い移動は「行き先へ移動」で、道路網の所要時間だけゲーム内時間がかかる。

## 7. 実装順序

1. 実行者つきコマンドと権限の確認（既存コマンドは世界創造者として動くまま）
2. 住民の名前・勤続・人間関係、操作中の人物の状態、保存形式 v2（v1も読める）
3. 1日の予定（Core）と AvatarSystem、Labor・Retail・Finance・Population の接続
4. 内装の定義と、出入り・設備・買い物・就職・会話・移動のコマンド
5. テスト（権限、連動、保存、既存テストの不変）
6. Web：モード切替、人物の選択・作成、一人称・三人称、内装、行動、状態表示、マウスルック・ジャイロ
7. ブラウザの自動テスト、公開

## 8. 技術的な課題

- 歩く速さと世界の時間の差（6章で対応）。
- 給料の比例払い・昇進が経済の均衡に与える影響 → 10年連続実行で確認する。
- 屋内の当たり判定は部屋の境界と設備の矩形のみ（第1段階）。
- 人物が死亡・移住しない例外は暫定（D4）。人生の終わり方は第2段階で設計する。

## 9. 実装状況（2026-10-17）

| 項目（第1段階 1〜7） | 状態 | 確認方法 |
|---|---|---|
| 1 人物の選択・新規作成 | ✅ | LifeModeTests、ブラウザ（選択・作成） |
| 2 一人称・三人称（＋俯瞰）での移動 | ✅ | ブラウザ（キー・スティックで歩行、壁・水面で止まる） |
| 3 建物に入り設備を使う | ✅ | 自宅（ベッド・冷蔵庫・ソファ）、店（レジ・売り場）、職場、市役所（求人掲示板）、学校（教室） |
| 4 時間・所持金・住まい・仕事の表示 | ✅ | 状態カードと「人生」タブ |
| 5 買い物と仕事 | ✅ | 在庫・価格・帳簿が実データ。給与は勤務時間に比例 |
| 6 シミュレーションとの連動 | ✅ | 雇用・小売・人口・財務の各システムと同じデータ。世界の時間は止まらない |
| 7 保存・読込で人物を維持 | ✅ | 保存形式 v2、ブラウザでも確認 |
| ジャイロ・マウスルック | 🌐 | 合成イベントで確認。実機センサーは未確認 |

未実装（第2段階以降）：世帯と家族関係、人生の節目（結婚・出産・老後・死）、建物内の住民の動き、乗り物の運転、細かな内装の生成、会話の内容。

## 10. 第2段階の一部（S2〜S4で実装）

- **家賃**：日ごとの家賃、滞納日数、30日で退去。
- **健康と診療所**：健康の値と、診療所で受ける治療。
- **公園**：ベンチで休める。
- **結婚**：プロポーズして、パートナー・子どもと暮らす。
- **未実装**：結婚式などの節目の演出、老後・相続の体験、操作中の人物の死、乗り物。
