# 超大規模3D世界シミュレーションゲーム 全体仕様書・試作版開発計画書 v1.0

- 開発方針： 多数の機能を簡易実装した試作版を作成し、世界全体のシステム連携を先に検証する。
- 開発支援： Claude Code
- 対応端末： PC、スマートフォン、タブレット
- 最終目標： 自由に編集できる広大な3D世界の中で、住民・企業・都市・国家・研究機関・自然環境・生態系が自律的に変化する、拡張性の高い世界シミュレーションゲームを開発する。

> 本ファイルはプロジェクトの正式な仕様書である。設計上の重大な変更は末尾の「変更履歴」に記録する。

## 第1章 ゲームの基本構想

### 1.1 ゲームのコンセプト

本作は、都市建設ゲーム、経営シミュレーション、人生シミュレーション、文明発展シミュレーション、自然環境シミュレーションを統合した、自由度の高い3D世界シミュレーションゲームである。

プレイヤーは世界の創造者・管理者として、地形、建物、道路、交通網、企業、住民、技術、政治制度、自然環境などを自由に編集できる。

一方、世界を構成する各主体は、プレイヤーの操作を待つことなく自律的に活動する。企業は利益や需要に応じて生産・採用・投資を行い、住民は仕事や住環境に応じて移動し、国家や都市は政策を変更する。技術革新、産業の発展、人口移動、環境変化などが連鎖して発生する。

本作の最も重要な特徴は、あらゆる要素が独立した機能ではなく、一つの世界の中で相互に影響することである。

### 1.2 基本原則

1. 最終的なゲーム構想を維持しながら、段階的に実装する。
2. 初期試作では多数の機能を簡易版として実装し、機能間の連携を検証する。
3. 住民・企業・自然環境などの状態を共通の世界データで管理する。
4. 詳細なシミュレーションと集約的なシミュレーションを使い分ける。
5. ゲームは常に実行可能な状態を保ち、各段階でテストする。
6. PC・スマートフォン・タブレットへの対応を設計段階から考慮する。
7. 将来の拡張、ユーザー制作コンテンツ、マルチプレイを妨げない構造を目指す。
8. 未実装機能を実装済みであるかのように表示しない。

## 第2章 最終目標とする機能

### 2.1 世界と地形
- 広大な地域に複数の都市、農村、山岳地帯、島、海岸、港湾、工業地域などを配置する。
- 自然地形の自動生成と、白紙からの世界作成に対応する。
- 地形の隆起・削平、河川の作成、海岸線の変更、人工島の建設を可能にする。
- 河川、海、降雨、地下水、地質、植生、資源などを相互に関連付ける。
- 地震、洪水、火山、地滑り、気候変動などを世界の状態に応じて発生させる。
- 地質・気候・生態系の変化を都市や文明の発展と結び付ける。

### 2.2 建築と都市開発
- 住宅、商業施設、オフィス、工場、公共施設、インフラなどを自由に建設する。
- 壁、床、柱、窓、扉、階段、屋根、廊下、部屋などを組み合わせるモジュール式建築を採用する。
- 将来的に寸法・頂点・辺・面などを編集する自由形状建築にも対応する。
- 建物内部への立ち入り、家具や設備の配置、室内の動線を扱う。
- 建物の配置や内部構造が、住民の移動、店舗の処理能力、工場の生産性などに影響する。
- 都市計画と建物内部の詳細な編集を同じ世界で扱う。

### 2.3 交通と物流
- 道路、交差点、鉄道、地下鉄、高架、トンネル、橋、港、貨物輸送網などを整備する。
- 交通容量、移動時間、渋滞、輸送費、物流量などをシミュレーションする。
- 乗客と貨物の流れを都市・企業・住民の活動に結び付ける。
- 交通網の改善が、雇用、地価、産業立地、企業収益などに影響するようにする。

### 2.4 住民と社会
- 住民ごとに居住地、職業、収入、年齢、教育、好み、移動先などの属性を持たせる。
- 通勤、買い物、通学、余暇などの生活行動を再現する。
- 就職、転職、転居、教育、家族形成、退職などのライフイベントを扱う。
- 長期的には世代交代、社会階層、人口構成、価値観の変化などを扱う。
- 遠方の住民は集約的に計算し、必要な場所では個人単位のシミュレーションを行う。

### 2.5 企業と経済
- 企業ごとに資金、従業員、在庫、生産能力、取引先、顧客、価格、投資計画などを管理する。
- 原材料から部品、完成品、販売までの生産網を構築する。
- 需要、供給、価格、賃金、輸送費、税金などを相互に関連付ける。
- 企業が需要や収益に応じて生産、採用、投資、撤退などを判断する。
- 企業間の競争、提携、技術導入、倒産、産業の盛衰を扱う。
- 企業活動の変化が雇用、人口、住宅需要、税収、地域経済へ波及するようにする。

### 2.6 工場と製造工程
- 工場内部に生産設備、搬送設備、作業場所、保管場所などを配置する。
- 製造工程、設備能力、材料消費、電力・水の使用量、故障、保守、歩留まりなどを扱う。
- 工場の配置や動線が生産効率に影響するようにする。
- 原材料不足、設備故障、熟練者不足などが生産停止や供給不足につながるようにする。

### 2.7 技術と文明
- 研究機関が技術を研究し、企業や国家が技術を採用する。
- 技術によって生産能力、輸送、エネルギー、通信、環境負荷などが変化する。
- 技術導入には資金、人材、設備、資源などが必要になる。
- 新技術による産業構造の変化、雇用への影響、環境上の副作用などを扱う。
- プレイヤーが新しい技術や研究分野を定義できる拡張機能を目指す。

### 2.8 政治・外交・安全保障
- 都市や国家が予算、税率、法律、産業政策などを管理する。
- 国家間の貿易、外交、関税、移民政策、資源交渉などを扱う。
- 国際的な協力や対立が経済、物流、技術導入、人口移動に影響するようにする。
- 将来的には防衛予算、装備調達、補給、地域防衛、紛争後の復興などを戦略レベルで扱う。

### 2.9 自然環境と生態系
- 気候、水循環、地形、植生、生物の分布などをシミュレーションする。
- 人間の活動による汚染、森林減少、資源消費、生息地の分断などを扱う。
- 動植物の繁殖、移動、個体数の変化、生態系への影響などを再現する。
- 長期的には進化や種分化を、世代交代と遺伝的変異を用いた近似モデルとして実装する。
- 自然災害や環境変化が社会や経済へ波及するようにする。

### 2.10 操作と情報分析
- 俯瞰視点、一人称視点、自由カメラ、人物の直接操作を統合する。
- 住民や作業員などを選択し、状態や行動を確認できるようにする。
- 人口、経済、交通、環境、技術、政治などを地図やグラフで表示する。
- 原因分析、地域比較、未来予測、歴史比較、AIによる改善提案などを提供する。
- 概要表示と詳細分析表示を切り替えられるようにする。

### 2.11 ゲームモード
同じ世界データとシミュレーション基盤を共有し、以下のモードを提供する。
- 自由創造モード
- 都市経営モード
- 国家運営モード
- 文明発展モード
- 災害・復興シナリオ
- カスタムシナリオ

### 2.12 時間・歴史・拡張
- 時間停止、通常進行、時間加速に対応する。
- セーブデータの複製による歴史分岐を実現する。
- 分岐ごとの社会、経済、政治、技術、自然環境を比較する。
- 独自の建物、企業、技術、資源、生物、法律、シナリオなどを追加できるようにする。
- 将来的には拡張API、作品共有、協力プレイ、国家間競争などを実装する。

## 第3章 最初の試作版の仕様

### 3.1 試作版の目的
最初の試作版は、最終版の全機能を完成させるものではない。
目的は、ゲームを構成する多数の機能を簡易版として一つの世界に実装し、一つのシステムの変化が、他のシステムへ正しく波及するかを検証することである。
見た目だけのデモではなく、実際に操作でき、時間が進み、状態が変化し、保存・再開できる試作を目指す。

### 3.2 試作版の初期世界
- 小規模な3D地形を自動生成する。
- 一つの都市と、その周辺の農地・森林・工業地域を用意する。
- 道路、住宅、店舗、工場、発電施設、公共施設を配置する。
- 住民、企業、資源、生産品、技術、環境データを初期化する。
- 時間進行とシミュレーションを開始できるようにする。

初期段階では、数千平方キロメートルの世界や数万人の個人を完全に詳細計算することを必須としない。小さな地域でも、主要なシステム間の連携を確認できることを優先する。

### 3.3 試作版に実装する機能

| 分野 | 試作版での実装 |
|---|---|
| 3D世界 | 地形、建物、道路、植生の表示 |
| 地形編集 | 地形の高さ変更、平坦化 |
| 建築 | 建物の配置・削除、基本的な道路建設 |
| カメラ | 俯瞰視点、自由カメラ、簡易的な一人称視点 |
| 時間 | 停止、通常進行、加速 |
| 住民 | 個人属性、住居、職場、通勤先、簡易的な生活行動 |
| 企業 | 資金、従業員、需要、生産、販売 |
| 製造 | 原材料、加工品、完成品の3段階程度の生産網 |
| 工場 | 設備能力、稼働率、材料不足、簡易的な故障 |
| 交通 | 道路網、移動時間、簡易的な交通量 |
| 経済 | 価格、賃金、企業収益、雇用、税収 |
| 技術 | 基本的な研究ポイントと技術効果 |
| 政治 | 税率や産業補助などの基本政策 |
| 環境 | 汚染、エネルギー消費、簡易的な天候 |
| 災害 | 一種類以上の簡易災害と復旧 |
| 情報表示 | 人口、収支、生産量、交通量、汚染のグラフ |
| 保存 | 世界状態の保存・ロード |
| 歴史分岐 | セーブデータを複製して別々の未来を進める |
| 拡張性 | 建物・企業・資源・技術などのデータ定義を外部化 |

上記の機能は、初期版では簡易モデルでよい。ただし、可能な限り共通のデータ構造を利用し、後から詳細なモデルへ置き換えられるようにする。

## 第4章 最重要の連携シナリオ

試作版の成否は、機能の数ではなく、システム間の連携によって評価する。

**シナリオA：工場から都市経済まで**
1. プレイヤーが工場を建設する。
2. 工場が原材料を購入し、生産を開始する。
3. 製品が店舗や他企業へ輸送される。
4. 生産増加に伴い、雇用や賃金が変化する。
5. 住民の所得や消費が変わる。
6. 都市の税収や人口動向が変化する。

**シナリオB：交通と産業の連鎖**
1. プレイヤーが道路を変更する。
2. 輸送時間や交通容量が変化する。
3. 工場の輸送費や納期が変化する。
4. 企業収益や商品の価格が変化する。
5. 雇用や地域の魅力が変わる。
6. 住民の転居や都市の発展に影響する。

**シナリオC：技術革新と社会変化**
1. 研究機関が新技術を開発する。
2. 企業が新技術を採用する。
3. 生産能力やエネルギー消費が変わる。
4. 雇用構成や商品価格が変化する。
5. 都市の財政や環境状態が変化する。

**シナリオD：災害と復興**
1. 災害によって道路や工場などが被害を受ける。
2. 輸送能力や生産能力が低下する。
3. 物資不足、企業収益、住民生活に影響が出る。
4. プレイヤーが復旧や防災投資を行う。
5. 復興速度や将来の災害への耐性を比較する。

これらのシナリオが動作すれば、単なる独立機能の集合ではなく、世界シミュレーションの基盤が成立していると判断できる。

## 第5章 技術構成の推奨方針

### 5.1 エンジン
第一候補はUnity 6系とする。
理由は、PCとスマートフォン・タブレットを同じ基盤から開発しやすく、3D描画、入力、UI、物理演算、データ管理などを統合しやすいためである。C#はClaude Codeによるコード生成・修正・テスト支援とも相性がよい。
描画にはまずURPを候補とし、実機性能を測定しながら品質設定を調整する。超高精細なグラフィックスよりも、広い世界と多数のシミュレーションを両立できることを優先する。
エンジンや主要パッケージの具体的なバージョンは、開発開始時に公式ドキュメントで互換性を確認して確定する。

### 5.2 アーキテクチャ
以下の機能を明確に分離する。
- World： 地形、建物、道路、地域、世界の基本データ
- Simulation： 時間進行、住民、企業、交通、経済、環境
- Presentation： 3D描画、アニメーション、カメラ、エフェクト
- UI： 建築メニュー、管理画面、分析グラフ、設定
- Persistence： セーブ、ロード、歴史分岐
- Content： 建物、企業、技術、資源、シナリオなどの定義
- Testing： 単体テスト、連携テスト、性能テスト

シミュレーションの計算を、描画フレームの更新と直接結び付けない。時間進行は独立した更新サイクルで管理し、同じ条件から可能な限り同じ結果を再現できる構造を目指す。

### 5.3 パフォーマンス
- 近距離の住民や工場は詳細に処理する。
- 遠方の住民や企業は集約データで計算する。
- 地形・建物・植生などは描画距離に応じて詳細度を変える。
- 経済や人口などの更新頻度は、現象に応じて分ける。
- 大量データの検索や更新では、必要に応じて空間分割やバッチ処理を導入する。
- プロファイリングでボトルネックを確認してから、必要な部分にデータ指向設計やJob Systemなどを導入する。

最初から全機能を複雑な並列処理にするのではなく、まず正しく動くモデルを作り、測定結果に基づいて最適化する。

### 5.4 データと保存
- ゲーム内の定義データと、実際のプレイ状態を分離する。
- 建物・企業・資源・技術などの定義は、可能な範囲で外部データから読み込む。
- プレイ状態には安定したIDを割り当てる。
- セーブには世界の状態、シミュレーション時刻、乱数状態、バージョン情報などを保存する。
- 歴史分岐は、まず独立したセーブデータの複製で実現する。
- 将来的に差分保存や履歴圧縮を検討する。

### 5.5 マルチプレイへの備え
マルチプレイは初期試作版では実装しない。
ただし、ゲーム状態と表示を分離し、世界の更新規則を整理し、保存形式にバージョン管理を導入することで、将来的なサーバー管理・同期・権限管理への移行を妨げないようにする。
将来のマルチプレイ対応を理由に、初期版の開発を不必要に複雑化しない。

## 第6章 開発計画

**フェーズ0：開発環境と土台** — プロジェクト作成／バージョン管理の設定／シーン構成と基本フォルダーの整理／3D地形とカメラの表示／入力方式の基本設計／テスト実行方法の整備
完了条件： PCで起動し、3D世界を表示してカメラを操作できる。

**フェーズ1：世界と基本操作** — 地形の生成／建物と道路の配置／地形編集／建築・削除操作／時間の停止・進行・加速／基本的なUI
完了条件： プレイヤーが世界を編集し、その変化を画面上で確認できる。

**フェーズ2：住民・企業・生産** — 住民データ／企業データ／原材料・製品・在庫／生産と販売／雇用と収入／基本的な物流
完了条件： 工場の生産が企業収益や雇用に影響する。

**フェーズ3：交通・都市・経済の連携** — 道路網／移動時間と交通量／輸送費／企業間取引／価格・税収・人口の更新／基本的な都市分析
完了条件： 道路や工場を変更すると、物流・経済・住民の状態が連鎖的に変化する。

**フェーズ4：技術・政治・環境・災害** — 技術研究／政策変更／エネルギーと汚染／天候と災害／被害・復旧／システム間の連携イベント
完了条件： 技術、政策、環境、災害の変化が都市経済に影響する。

**フェーズ5：保存・分析・歴史分岐** — セーブ・ロード／データ複製／分岐ごとの独立した時間進行／人口・収支・交通などのグラフ／分岐間の統計比較
完了条件： 同じ時点から二つの未来を作り、異なる結果を保存・比較できる。

**フェーズ6：試作版の統合と最適化** — 全システムの連携確認／長時間のシミュレーションテスト／保存・ロードの検証／不具合修正／PCでの性能測定／スマートフォン・タブレット向けの操作・描画検証
完了条件： 一つの世界で建築、住民、企業、交通、経済、技術、環境、災害、保存、歴史分岐が連携する試作版が安定して動作する。

## 第7章 品質基準と制約

### 7.1 必須の品質基準
- 起動不能や進行不能につながる重大な不具合を残さない。
- セーブ・ロードによって主要な世界状態が失われない。
- 時間加速によってシミュレーションの状態が不整合にならない。
- 経済の数値が理由なく増減しないよう、収支と資源移動を検証する。
- システム間の連携を自動テストできるようにする。
- モバイル端末では性能に応じて描画品質やシミュレーション規模を調整する。
- 未実装の機能は、動作する機能と区別して表示する。

### 7.2 試作版で割り切ること
初期試作版では、以下を完成条件に含めない。
- 数十万人以上の住民をすべて個別に詳細シミュレーションすること
- 世界全体の精密な気象・地質・進化計算
- 工場内部のすべての設備や作業員の完全再現
- 任意の複雑な形状を扱う高度な建築エディター
- 本格的な戦争・外交AI
- 完全なユーザーコード拡張機構
- オンラインマルチプレイ
- あらゆる端末で最高品質の3D表示

これらは最終目標として維持し、基盤が安定した後に順次実装する。

### 7.3 開発中の判断基準
1. 世界の主要な連携に必要か。
2. 現在の機能を壊さず追加できるか。
3. テストによって正しさを確認できるか。
4. PCとモバイルの性能に与える影響を測定できるか。
5. 将来の詳細化を妨げないデータ構造になっているか。

## 第8章 Claude Codeへの開発指示方針

Claude Codeには、最初からすべての機能を一括生成させない。
まず本書をプロジェクトの仕様書として保存し、開発計画を読み込ませたうえで、各フェーズを小さな作業単位に分割する。

各作業では、以下を必須とする。
1. 既存のプロジェクト構成とコードを確認する。
2. 実装内容と変更対象を明示する。
3. 必要なコードを実装する。
4. ビルドやテストを実行する。
5. エラーや既存機能への影響を修正する。
6. 実装済み機能、未実装機能、既知の問題を報告する。
7. 次の作業に進む前に、動作可能な状態を保つ。

一度に変更する範囲を必要以上に広げず、重要な機能にはテストを用意する。テストが実行できない場合は、その事実を明示し、成功したと報告しない。
また、設計上の重大な変更は、仕様書と開発計画に反映する。

## 最終方針

本作は、自由な世界編集と、自律的に発展する文明シミュレーションを統合した大規模ゲームを目指す。
最初の試作版では、建築・住民・企業・生産・交通・経済・技術・環境・災害・保存・歴史分岐を簡易的に実装し、世界全体が連動することを確認する。
その後、計算性能、操作性、データ構造、各システムの精度を検証しながら、詳細な建築、個人の生活、精密な工場、生態系、文明の長期発展、拡張機能、マルチプレイへと段階的に発展させる。
目標は小さなゲームで妥協することではない。最終的に壮大な世界を実現するために、まず世界全体が動く基盤を作ることである。
