## 既知の課題

- Unity版は表示・操作コードのみで、Unity上での実行確認は未実施。Unity版には政策・研究・分岐などの画面がまだ無い（Web版にはある）。
- 既定の町は失業率が約10%前後で落ち着く設計。政策や建設で改善できるが、自動で均衡するわけではない。
- 渋滞は道路を一本に集中させたときに発生する程度で、既定の町ではほぼ起きない。
- 大きな町の計算量：S5-1で、約7,300人の町で1日338ms→約60msに改善（BENCHMARKS.md）。まだ人口に対して2乗に近い部分（住まい×店の表）が残る。
- ブラウザ版は事前コンパイル（AOT）なしの通訳実行で、既定の町では .NET の約3倍遅い（S5-3で検討）。計測値は [BENCHMARKS.md](BENCHMARKS.md)。
- ブラウザ版の保存先はその端末のブラウザ内（容量・消去に注意）。書き出し文字列で持ち出せる。
- ジャイロは実機センサーでは未確認（自動テストは合成イベント）。claude.ai の埋め込み表示ではセンサーが遮断される可能性が高く、その場合は案内が出る。単独のページ（例：GitHub Pages）なら iPad で使える見込み［推測］。
- 人生体験：「同じ住まいの人」は同じ住宅建物の住民（世帯・家族関係はまだ無い）。建物内の他の住民は予定に基づく人数・顔ぶれで、建物内を歩き回る動きは無い。人物の死亡・自動移住はしない（D4 暫定）。
